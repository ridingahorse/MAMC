2. Key Technical Concepts:
   - **CiA402 PV mode (0x6060 = 3)** data flow: master TPDO (0x202 / 0x204) → slave RPDO1: control word 0x6040(16) + target velocity 0x60FF(32); slave TPDO1 (0x182 / 0x184) → master RPDO: status word 0x6041(16) + actual velocity 0x606C(32).
   - **Sync-receive RPDO semantics** (the user's stated definition): master may send at any time; the slave buffers the frame and only writes it into its object dictionary when a SYNC arrives; between two SYNCs only the **last** received frame survives. Enabled by `use_sync` → `canopen_init` writes the slave-side RPDO tx_type = 0x01 (only for RPDO channels, `comm_idx` 0x1400–0x15FF; TPDOs keep their async config).
   - **`use_sync` side effects** (canopen_init.c:309-316, ~393-404): overrides only the slave-side RPDO transmission type to 0x01; the first config with `use_sync` also configures the master as SYNC producer once (`OD_set_u32(OD_ENTRY_H1005, 0, 0x40000080u, false); OD_set_u8(OD_ENTRY_H1019, 0, 0u, false); OD_set_u32(OD_ENTRY_H1006, 0, cfg->sync_period_us, false);` — period 0 = manual SYNC only).
   - **Old-firmware PV ignition:** control-word bit8 (Halt) 1→0 falling edge required once per entry into PV; 0x60FF must be written first; the pulse is needed only once per PV entry. Sequence = 6 alternating steps (0: ①frame 0x000F+target, 1: SYNC, 2: ②frame 0x010F, 3: SYNC, 4: ③frame 0x000F, 5: SYNC), `CIA402_HALT_GAP_MS = 20U`.
   - **Control word 0 is fatal:** a frame carrying 0x6040 = 0 drops the drive to Switch On Disabled (statusword bit6, `0x0670`); from there 0x000F cannot recover — the full 0x06 → 0x07 → 0x0F sequence is needed. Observed healthy: node2 `0x0637`, node4 `0x0227`; dead: `0x0670`.
   - **`trans_step` aliasing bug:** `trans_step` was shared between the 402 transition sub-step (0 = write ctrl, 1 = read statusword) and the PV ignition step counter.
   - **Deferred enter:** `fsm_dispatch` runs `fsm_enter(s)` only when `s->state != s->prev_state`, on the **next** `cia402_process` call after the state is assigned — creating a one-tick window.
   - **Master-side PDO mapping is RAM, not EEPROM:** `apply_master_pdo_mapping()` writes `cfg->master_mappings` into the master's OD objects (0x1A00/0x1600/0x1A01/0x1601) then calls `CO_CANopenInitPDO()`. OD.c defaults happen to match channel 1 (0x1A00 = 0x20000010 + 0x20020020; 0x1600 = 0x20030010 + 0x20050020) but 0x1A01/0x1601 default to count **0**.
